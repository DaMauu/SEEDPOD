## 概述

把原盘搬运里规则明确、判断固定的重复劳动收进一个挂起面板：按规则筛合格原盘、跨站查重、BDInfo 排版、截图转存、填单推种。Tampermonkey 单文件脚本，约 6300 行，无构建、无依赖、无后端，适配 NexusPHP / UNIT3D / Gazelle / f3nix。

## 能力概览

- **批量审核**：按介质、编码、体积、禁转标签逐条判断，可发条目自动入队。
- **跨站查重**：IMDb → 片名 → AKA 原名 → 完整片名四段回退，命中后按 4K 属性与体积复核。
- **断点续跑**：记录页号、列表地址与已查种子；重登后自动跳回断点页；两次拉取默认间隔 10 分钟；断点与总页数不符时自动纠偏。
- **前端渲染站点翻页补渲染**：手动翻页后用本地词库就地补徽标，零网络请求。
- **自动翻页兜底**：后台请求拿不到新页时，改成像人一样点站点自己的「下一页」，逐页记账、跳转后自动续跑、到头自动接查重；可随时暂停，带单次页数上限。
- **翻页抗限流**：自适应降速（触发限流后按 1.4 倍递增间隔并持久化）+ 小时配额守卫（默认 90 页/小时）+ 三级退避（60s/180s/300s）；未抓完不会误报完成。
- **本地词库**：按目标站分区、分片存储、带有效期，支持导入导出。
- **截图保真**：候选地址逐个测宽取原图，二进制上传，返图尺寸复核。
- **简介图片全转存**：截图与豆瓣海报等简介内图片统一转存图床；同名文件直接复用已有图床链接，图床判重时保留原链不报错。
- **转种填单**：BDInfo 表格重建、副标题排版、种子注入、字段锁定、标题守卫。
- **推送下载**：推送到 qBittorrent 并自动补设分类。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 打开 [`scripts/bluray/legacy/pt-bluray-assistant-v0.0.0.47.user.js`](scripts/bluray/legacy/pt-bluray-assistant-v0.0.0.47.user.js)，点 `Raw` 确认安装。
3. 刷新站点，右上角出现「原盘转载面板」即成功。

## 反复出现与未解决的问题

记录**修过又复发**或**至今未根治**的问题，供后续接手者判断新旧。状态：`未解决` 根因仍在只是绕开；`反复` 修过多次仍复发；`已缓解` 有兜底但触发条件未消除；`已修复` 确认根因消除。

### K-01 截图传上去仍是缩略图 · 反复

简介里的图片只有 400px 左右，点开也不是原图。源站用 `[url=原图][img=400]缩略图[/img][/url]` 书写，缩略图与原图是两个地址，图床按 URL 抓取时还会再压一次。

尝试过：后缀还原、代理地址解包、候选地址逐个测宽、二进制上传、返图尺寸复核、查看页取 `og:image`、测不到宽度时不退回缩略图。

现状：链路已按“取原图”重写，但缺少真实页面上的闭环证据；日志会打印每张图的最终地址与宽度。下一步用一次完整日志比对 `原图确认` 与 `图床已转存` 两行的宽度是否一致。

### K-02 图床返回“重复上传” · 未解决

第二次上传同一张图失败。图床按内容哈希判重，脚本拿不到已存在图片的 URL，目前视为已存在并保留原链，不再刷屏报错。

### K-03 目标站改写标题 · 已缓解

上传页标题被替换成内部文件名（如 `LENNEMI.PUBLIC.N1`），因为站点在种子注入后按 `info.name` 回填。现用“文件名=源站标题 + 标题守卫”压制，守卫结束后仍可能被回填，发布前需扫一眼。

### K-04 面板布局反复错位 · 反复

方块不等高、列宽被内容撑开、按钮换行、分割线偏移、日志变长带动方块变形。根因是 `1fr` 受 min-content 影响、`aspect-ratio` 与内容高度耦合、样式表被内联或旧样式覆盖。已固定为 `minmax(0,1fr)`、固定行高、`min-width:0`、容器溢出隐藏、列间距归零后用对称内边距让分割线居中。缺自动化视觉回归，改动仍需人工确认。

### K-05 用 PowerShell 拼接代码破坏语法 · 反复

改完报语法错，或出现重复行、少花括号。CRLF 与中文块导致字符串替换失配，按行号拼接时索引偏移。约束：优先用精确替换工具，必须拼接时立刻 `node --check`，并确认函数仍在顶层。

### K-06 函数被误插入另一个函数体内 · 已修复（有复发风险）

语法检查通过但运行时报 `xxx is not defined`，因为声明落进了上一个函数体。已把截图相关函数提升到顶层，同类风险见 K-05。

### K-07 查重误判“已有原盘” · 已缓解

目标站明明没有却标记冲突，导致漏发。早期只按“是否原盘”判定，AKA 搜索命中的同名条目被当作重复。现改为 `4K 属性一致 && 体积差 ≤1%` 双条件，并取消发布时二次复检。词库中旧规则结论仍在有效期内，需用「二查」刷新。

### K-08 目标站 429 与被踢下线 · 未解决

连续查重后返回 429 或被打回登录页，属站点限流。现检测到登录页或 403 立即中止并保留断点，429 退避 60 秒，查重间隔 ≥4 秒、每 10 条歇 30 秒。阈值不可预知，只能被动退避。

### K-09 前端渲染站点翻页卡死 · 已缓解

翻到某页后停住，页码不前进。已放宽活动页判定、以行内容变化作兜底、必要时点击页码重试；仅在少数页面验证过。

### K-10 断点失效导致从第 1 页重来 · 已缓解

早期断点要求列表地址完全一致，重新登录或改筛选即失配。现只比较站点对与保存时间；切换站点或改目标站仍会重来，属预期行为。

### K-11 字段粘连的 BDInfo · 已修复

部分站的 BDInfo 把多个字段粘在同行（`bytesProtection:`、`MPLSSize:`、`1080iAudio:`），逐行解析全部失效。现在解析前先做一次字段级归一化：识别 12 个已知字段标签，若标签前紧贴非空白字符则补换行，再逐行匹配。回归用例覆盖“粘连文本正确拆分”与“正常文本不得被拆坏”两种情况。

### K-12 图床压缩长图 · 未解决

上传成功但返图更窄，属图床侧策略。检测到返图更小则回退原链，简介里出现的是源站原图地址。

### K-13 新站点接入只审当前页 · 已修复

`multiPage` 白名单只列了 unit3d / np / gz，f3nix 漏在外面，于是「拉取数据」只审屏幕上那一页就宣告结束，几百页的名单一条也没抓。修法是：白名单补 f3nix，翻页循环加 f3nix 分支（行解析、页码上限、末页原地打转检测、每 30 页歇 90 秒），断点 `lastPage` 也按站点页码校验。教训是新增站点适配时，翻页白名单和循环内解析两处必须同时补，漏一处就是静默失败、日志还显示「完成」。

### K-14 后台翻页抓回同一页 · 已缓解

f3nix 的行链接是 slug 不是数字 id，早期拿「数字 id 是否存在」当唯一键，结果所有行都被判成无效，日志显示「新增 0 条」，紧接着又因为前后两页签名相同停在第 2 页。现在唯一键退到详情地址，页码参数从分页器实测反推，并打印地址模板与首行诊断；一旦发现抓回来的内容和当前页或上一页完全相同，只保留断点、不再标记完成，免得把「没抓到」记成「抓完了」。实测 BHD 的列表筛选存在站点侧，后台 GET 换页拿回来的还是同一页，所以这类站点最终走「自动翻页」：由脚本点站点自己的下一页，靠 GM 存储把页号、名单、已走页数带过每一次跳转。

### 复发规律

1. 依赖地址规则的推断总会漏：后缀、链接形态、字段命名，规则补不完，应以实测宽度与内容为准。
2. 大段替换代码容易破坏结构：优先小步编辑。
3. 布局靠内容自适应就会变形：显式固定尺寸加溢出兜底最稳。
4. 站点侧行为只能兜底：限流、标题回填、图床压缩，脚本只能减小影响，不能消除。
5. 站点适配不止一个入口：`AUDIT_HANDLERS`、`PRESET_HANDLERS`、`siteUrl`、翻页循环、详情穿透，五处齐了才算「支持」。
