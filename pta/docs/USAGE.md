# 使用流程（按面板现在的样子）

这份是照着界面一步步走的操作说明；接口细节看 API.md，规则含义看 RULES-TREE.md。

## 一、准备工作

1. 打开面板，用面板账号登录（账号密码在测试机上由环境变量给，界面不能改）。
2. 去「站点」页，搜索要抓的站，点开抽屉。
3. 「登录」页签：把浏览器里登录后的整段 Cookie 粘进去，点「保存设置」。保存后这里会显示「已保存 + 更新时间」，并自动用已存的 Cookie 自检一次，结果会留在页签上。
4. 同一抽屉里可以改架构、地址、每天抓几次；「单独设置本站」打开后这些覆盖才生效（间隔与次数仍被全局 30 秒 / 每天 20 次压住）。

## 二、抓取

1. 到「流程」页，右上角「选来源站」挑一个站，选这一轮抓多少条（5/10/20/100）。
2. 想先看会请求什么地址，点「看地址」：显示 URL、分类、间隔、每日上限、今天已抓几次；可以翻上一类/下一类，也可以「抓这一类」只抓当前分类。
3. 点「抓一页」：会发一次 GET，结果进「数据清单」。没有 Cookie 会直接被拒，不会去猜登录。
4. 抓取标记（禁转/独占/DIY/限转/未满 7 天）只打标不过滤；未满 7 天是按行里的发布时间算的，标签上有剩余天数。

## 三、查重与筛选

1. 去「数据清单」，按站点/类型/状态/标记筛。
2. 点「查重」：跟待审核、本地库、已送审/已发布的词条比对，重复的标「已有」，鼠标停在「已有」上能看到撞了哪条。
3. 点「按条件送审」：先查重，再按流程页「查重」里的条件（分辨率/体积/中字/排除与白名单正则）处理；符合的进待审核，不符合的标跳过。
4. 「归档已跳过/已有」把跳过项和标已有的新词条一起归档；归档后行内可以点「恢复」退回待筛选。

## 四、发布

1. 去「待审核」，点条目看发布表单：标题、副标题、简介、图床、匿名、目标站。目标站必须选，没选会被拦下并说明。
2. 点「草稿预览」用后端拼草稿，同时显示识别出的发布标签和缺项（缺副标题/截图不足等）。
3. 截图在右栏上传，浏览器会先压到 1600px，服务端按条目存，最多 12 张。
4. 点「通过并发布」只做记账（词条标已发布，写发布记录）；真正去目标站发帖没有自动化，按项目铁律不做。

## 五、常见问题

- 保存 Cookie 后看不到值：输入框不回显是故意的，只看「已保存 + 时间 + 自检结果」。
- 「每天抓几次」不是条数：它是次数上限；一轮抓多少条在上面的 5/10/20/100 里选。
- 抓一页和看地址的分类不一样：看地址是预览某一类，抓一页会按类目轮转，想抓预览那类就点「抓这一类」。
- 待审核列表一次最多 500 条，到上限会提示；截图只在打开条目时才取，列表本身不带大图。
