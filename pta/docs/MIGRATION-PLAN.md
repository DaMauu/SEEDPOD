# 前端逻辑搬迁计划（legacy → SFC）

目标：把 `pta/web-src/src/legacy/app.js` 里的页面逻辑逐步搬进对应 SFC，直到 legacy 只剩路由、登录、共享工具。
线上始终服务 `pta/web/dist`，每页拆完都能单独上线。

## 每页完成定义（DoD）

全部满足才算完成，缺一条不算：

1. 该页的 legacy `initXxx()` 从 `boot()` 移除，且不再被调用。
2. 数据、状态、事件在 SFC 内；允许复用 legacy 的纯工具函数，但不新增 DOM 拼接逻辑。
3. 接口路径与字段不变；需要改先停，写 `docs/API.md` 提案。
4. `npm run build` 通过。
5. `node pta/checks/build.js` 7/7。
6. 线上手动验收清单逐项通过（见下），0 个 console error / pageerror。
7. 版本 +0.0.1，`CHANGELOG.md`、`HANDOFF.md` 更新，本文件勾选。
8. 部署后 `/api/health` 正常，该页在线上打开无报错。

## 每页验收清单

- **总览**：统计数字、实时日志、最近发布、待审核、系统状态五块都有数据或明确空状态。
- **设置**：版本模式切换生效、面板账号只读、系统信息与 `/api/dev` 一致。
- **待审核**：列表筛选、详情、草稿预览、通过/驳回、截图上传。
- **数据清单**：筛选、分页、归档、导出、查重按钮。
- **站点**：搜索/筛选、打开抽屉、页签切换、批量设置、连接自检。
- **流程**：规则组展开/保存、请求限制、演练、下载器弹窗。

## 停止条件

任一条命中就停下，写进 `TASKS.md` 并说明，不许猜：

- 需要改接口、字段或数据模型。
- 交互含义不明确，两种做法都合理。
- 同一页检查连续两轮不绿。
- 需要新增运行时依赖或构建工具。
- 涉及真实站点、cookie、面板密码。
- 单页改动超过 8 个文件或 400 行（先拆小，再继续）。

## 自主边界

- 只改 `pta/web-src`、`CHANGELOG.md`、`HANDOFF.md`、`TASKS.md`、`package.json`、本文件。
- 不碰 `pta/web`、`pta/server`、`data/`、真实站点。
- 旧函数先停止调用，不急着删；全部拆完再统一清理。
- 不改视觉风格和文案，只做等价搬迁。
- 不引 Pinia、UI 库、CSS 框架。
- 部署只在检查全绿后执行；失败回滚该提交。

## 交付节奏

- 一页一提交：`0.7.xx 拆 <页面> 到 SFC`。
- 每页提交后 `bash deploy.sh`，线上验收该页，失败 `git revert` 并标 blocked。
- 流程：读 legacy → 写 SFC → 删 boot 调用 → build → build.js → 线上点一遍 → 提交 → 部署 → 更新本文件。
