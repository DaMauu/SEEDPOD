# 界面规范（DESIGN）

面向个人使用的工具面板：信息密度可以高，但必须能扫读。所有改动先对照本文件，再动 `pta/web-src/src/styles/index.css` / `src/views/*.vue`。

## 一、设计变量（只准用这些）

来自 `pta/web-src/src/styles/00-base.css` 的 `:root`，不要新增同义色值。

CSS 清理规则：只删被后续同选择器/同媒体上下文完全覆盖的规则，只合并相邻同选择器，只删规则内同属性重复声明；不跨规则移动声明。

响应式布局以 `pta/docs/RESPONSIVE.md` 为准：一套 Vue 代码，断点 600/900/1320，验收 360/390/768/1280（新增页面加 1440）。页面样式迁移：共用 base / shell / components / responsive / dock 留 `src/styles/`；页面专属规则进对应 SFC `<style scoped>`；页面最外层 `.view[data-view=...]` 用单选择器 `:global`；一次一页，迁完删全局页面模块。子组件内部用 `.page-root :deep(.child)`，共享组件基础规则留全局。 页面专属主题（如日志页黑绿终端）和窄屏行布局也放页面 SFC，不留在共用模块。 窄屏（≤700px）优先保证名称、标签和控件可读：次要列可隐藏，成对字段纵向排，卡片头部按钮不压缩、允许换行。 Settings 的 `#set-panel` 规则迁 scoped 时保留 ID 前缀，避免特异性下降后被共用 `.set-field` 覆盖。 长标题行用 `minmax(0, 1fr)` 约束轨道，行内项加 `min-width: 0`；操作按钮区允许换行，不能靠隐藏溢出来伪装不滚动。 更新日志是 Markdown 只读页，解析和渲染放页面 SFC，正文卡片加 `overflow-wrap:anywhere` 防长串撑宽。 移动端列表优先整页滚动，不再套一层内部滚动；筛选栏用两列网格，操作按钮成对排列。 下载器卡片和弹窗表单在 ≤600px 改两行/单列，不保留固定五列网格。 页面最外层 `.view[data-view=...]` 规则放对应 SFC 的 `:global`；子组件抽屉头用 `.drawers :deep(.drawer-*)`。

## 流程页布局冻结（2026-11-18）

流程页（`#crawl`）的排布按当前效果冻结，非用户明确要求不要改：

- 初筛与查重合并成一张卡：左列初筛、右列查重，各字段纵向排列；一个保存按钮同时保存两边。
- 发布卡：④–⑧ 五列，列内纵向排；1200px 以下 3 列，800px 以下 2 列，600px 以下 1 列。
- 发布目标站是行内控件，无外框；“更换”按钮单行。
- 改动流程页 UI 必须：用户明确要求 → 改 `Crawl.vue` → `node pta/scripts/ui-freeze.js --update` → `pta/checks/run.sh` 全绿。
- `smoke-live` 已加布局断言：发布卡 5 列、5 个分组、初筛与查重卡 2 列/2 组/至少 10 个字段；改坏会直接失败。

## 二、组件白名单

只准用现有组件，不准为单个页面新造一套。

| 组件 | 类名 | 用途 |
| --- | --- | --- |
| 卡片 | `.card` + `.card-head` | 一个卡片只做一件事，标题是名词，≤ 6 字 |
| 按钮 | `.btn` / `.btn.primary` / `.btn.ghost` / `.btn.danger` / `.btn.sm` | 一个区域最多一个主按钮 |
| 输入 | `.input` / `.select` | 高度跟随现有，不自定义 |
| 开关 | `.switch` | 二元状态；能用默认值就别加开关 |
| 标签 | `.pill` | 顶部状态，不超过 5 个 |
| 芯片 | `pick` / `custom` 行 | 选项 ≤ 8 个用芯片，超过用下拉 |
| 手风琴 | 流程页现有结构 | 每组 ≤ 8 行，组头一行说明 |
| 抽屉 | 站点、条目详情 | 不改宽度与进入方式 |
| 表格 | 数据清单 | 不横向滚动，列数 ≤ 7 |
| 提示 | toast | 成功/失败各一种，2.5 秒消失 |
| 空状态 | 现有 `.empty` | 一句话说明 + 一个下一步按钮 |

禁止：新色值、渐变、玻璃拟态、图标库、阴影叠加、超过 150ms 的动画、`position: fixed` 的营销式浮层。

## 三、布局

- 桌面：4 列紧凑控件，或 2 列卡片；一行不超过 4 个可操作控件。
- 平板 768：2 列；手机 390：1 列。
- 流程页的「标签 + 控件」行：标签列固定 `104px`，控件自适应。
- 首屏必须能看到本页最重要的那张卡，不被标题区挤走。
- 卡片之间间距 `16px`，分区间距 `24px`。

## 四、文案

- 标签用名词：`分辨率要求`，不写 `设置分辨率要求`。
- 说明一句话，≤ 20 字，说人话：`太快会出验证码`，不写 `请求频率超过阈值将触发风控`。
- 错误提示说「怎么办」：`目标站没选，选一个再发`，不写 `targetSite is required`。
- 数字带单位：`5 GB`、`30 秒`、`2 次`。
- 不用感叹号，不用「请」开头的长句。

## 五、交互

- hover 只改背景/边框，不改尺寸。
- 焦点必须可见：`outline` 或 `box-shadow`，沿用 `.input:focus`。
- 破坏性操作二次确认；确认按钮用 `.btn.danger`。
- 保存成功用 toast，不弹窗；失败留在原地并显示原因。
- 动画只做 `opacity` / `transform`，时长 150ms；`prefers-reduced-motion` 下关闭。

## 六、验收清单（每次改页面都过一遍）

1. 1280 / 768 / 390 三个宽度截图，无横向滚动。
2. 首屏能看到本页主卡；流程页首屏至少露出两个手风琴组头。
3. 每个手风琴 ≤ 8 行（高级折叠内不计）。
4. 所有可点元素有 hover 与 focus 态。
5. 控制台无报错；`node pta/checks/audit.js` 无新增问题。
6. 文案过一遍第四节，不出现实现术语。
7. 旧配置回填后值不变。
8. 对比改前改后截图，差异说得清。

## 七、流程页补充规则

- 每组组头一行说明，≤ 20 字，回答「这段在管什么」。
- 新增条件先过 `pta/docs/RULES-RECONCILIATION.md` / `RULES-TREE.md` 的复杂度预算，再进 `pta/web-src/src/data/rules.js`。
- 高级项默认收起，组头显示「高级 · N 项」。
- 档位（简洁/标准/严格）只改默认值，不锁死单项；切档后显示「改了哪几项」。
- 任何新条件必须能回答：不设会怎样、默认值是什么、在哪关掉。
