# 响应式布局计划（RESPONSIVE）

状态：2026-11-17，v0.7.161。八个页面已完成页面级 `<style scoped>`；全局 `.view[data-view=...]` 页面选择器已清零。本文是后续页面和改动的执行标准。

## 一、目标与边界

- **一套 Vue 代码**同时服务桌面和手机，不维护独立的 `m.` 站或第二套前端。
- 允许**组件级换布局**：桌面表格 → 手机卡片、侧栏 → 底部导航、并排卡片 → 单列。
- 共用样式只放 `pta/web-src/src/styles/` 的 base / shell / components / responsive / dock。
- 页面专属规则进对应 SFC 的 `<style scoped>`；页面最外层 `.view` 用单选择器 `:global(.view[data-view=...])`。
- 子组件内部用 `.page-root :deep(.child)`，不把子组件基础规则复制进页面。
- 不碰真实 PT 站；真发布默认关。

## 二、断点

| 宽度 | 定位 | 主要动作 |
| --- | --- | --- |
| ≤600px | 手机 | 单列、隐藏次要列、筛选两列网格、按钮换行、卡片两行 |
| 601–900px | 平板 / 大屏手机 | 列表与详情全宽、抽屉头换行、筛选自然换行 |
| 901–1319px | 桌面窄屏 | 保持桌面密度，局部两列 |
| ≥1320px | 宽屏 | 完整布局，侧栏/多列 |

验收宽度固定为 **360 / 390 / 768 / 1280**；新增页面再加 **1440**。现有 1000 / 1100 / 1240 是历史局部断点，能合并就合并，不为统一而大改。

## 三、固定规则

### 1. 弹性布局

- 长内容列用 `minmax(0, 1fr)`，行内项加 `min-width: 0`。
- 一行放不下就 `flex-wrap: wrap`，不要靠缩小字号硬塞。
- 控件不压缩：按钮/徽标 `flex: 0 0 auto; white-space: nowrap`。
- 字号/间距用 `clamp()`，不写死大段像素。

### 2. 表格与列表

- 桌面表格在窄屏改成卡片，不横向滚动。
- 次要列可隐藏（如站点「抓取 / 上次抓取」），主名称必须完整显示；长名称允许换行。
- 列表在手机上取消内层滚动，随整页滚动；不要出现“只露出 4 条”的嵌套滚动。
- 卡片同一容器内必须同宽、左对齐；不允许列表 264px、详情 366px。

### 3. 筛选栏与操作区

- 小屏筛选栏用两列网格：搜索/目标站占整行，按钮两列，导出类独占一行。
- 操作按钮允许换行，靠左排列；不把“送审/归档”挤出屏幕。
- 空态卡片与正常卡片同宽。

### 4. 文字与徽标

- 「未接」等状态徽标固定在标签文字右侧；标签列用 `fit-content(220px)`，窄屏标签在上、控件在下。
- 长串用 `overflow-wrap: anywhere`；标题按场景选择换行或省略，不能默认全部省略。
- 禁止用 `overflow-x: hidden` 掩盖布局溢出；必须让内容换行或重排。

### 5. 外框与组件

- 页面外层：`:global(.view[data-view="..."])` 单选择器，不写 `:global(...) 后代`。
- 子组件：`.drawers :deep(.drawer-head)` 这类写法，并限定在页面根下。
- 共享组件基础规则留全局；页面主题、行布局、窄屏覆盖进页面 SFC。

## 五、验收流程

每次 UI/样式改动：

1. `npm run build`
2. 在 **360 / 390 / 768 / 1280** 打开改动页面（新增页面加 1440）。
3. 用最坏数据：空数据、长标题、305 站长列表。
4. 每页检查：
   - `document.documentElement.scrollWidth > innerWidth` → 有横向滚动
   - 按钮 `scrollWidth > clientWidth` → 文字被压
   - 列表/详情/卡片左右边缘是否对齐
   - 列表能否滚到底，分页是否可见
5. 跑 `bash pta/checks/run.sh`（含质量审计）。

Playwright 最小检查：

```js
const bad = await page.evaluate(() => ({
  doc: document.documentElement.scrollWidth > innerWidth,
  body: document.body.scrollWidth > innerWidth
}))
```

## 七、明确不做

- 不做独立移动站、两套前端、两套业务逻辑。
- 不为了响应式重写 UI 框架或引入 CSS 库。
- 不用 `overflow-x: hidden` 掩盖横向溢出。
- 不追求桌面和手机布局完全一致；按信息优先级重排。

## 八、维护约定

- 新页面必须同时具备：页面 scoped 样式、移动端规则、三/四宽度验收。
- 共享模块新增规则前先问：这是所有页面都用，还是单页？单页就进 SFC。
- 每轮 UI 改动在 CHANGELOG 记一句；跨页规则变化同步更新本文。
