# 需求卡模板

每次改动先落一张需求卡，放在 `pta/docs/requirements/YYYY-MM-DD-<slug>.md`。
作用：新会话不用重讲背景；验收有依据；以后能查到「为什么改成这样」。

没有需求卡就不动代码，例外只有改错别字。

## 模板

```md
# <一句话标题>

日期：YYYY-MM-DD
状态：讨论中 / 待实现 / 已实现 / 已放弃

## 背景
为什么现在要改。用户看到的实际问题，不写技术方案。

## 目标
改完能做什么，必须可验证。最多三条。

## 不做
这次明确不碰什么，防止范围膨胀。

## 规则变更
| 动作 | 条件 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 新增 / 合并 / 删除 | | | |

## 涉及位置
- 页面 / 路由：
- 前端文件：
- 后端接口：
- 数据字段：

## 验收
- [ ] `pta/checks` 全绿
- [ ] 页面实测（写具体点哪个控件）
- [ ] 旧配置回填不变
- [ ] 三宽度截图

## 风险
最坏会怎样，怎么回滚。
```

## 填写示例

```md
# 详情页抓取开关

日期：2026-11-13
状态：已实现

## 背景
列表只有标题和体积，发布时需要简介、BDInfo、截图，得再进详情页。

## 目标
- 抓取时可选择是否进详情页，最多 10 条
- 失败不中断本轮，只记 detailNote

## 不做
- 不默认开启，避免对真实站点加压
- 不改发布流程

## 规则变更
| 动作 | 条件 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 新增 | 抓详情页 | 关 | 每条都计入窗口次数与最小间隔 |

## 涉及位置
- 页面：流程 › 抓取 › 拉取
- 前端：`pta/web-src/src/data/rules.js`、`pta/web-src/src/views/*.vue`
- 后端：`pta/server/adapters/details.js`、`crawl.js`
- 字段：`config.detail`

## 验收
- [x] adapter 19 项全绿
- [x] 开关 false→true 落库，页面无 JS 报错
- [x] 真抓取默认关，未向真实站发请求

## 风险
真实站版式与夹具不同，解析可能留空；已用「认不出留空不猜」兜底。
```

## 写不出需求时

把抱怨原话丢给 AI，让它按模板填，你只改三处：目标、不做、验收。
填完还是说不清，说明这件事还不该做。
