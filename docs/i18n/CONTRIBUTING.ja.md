### このリポジトリの形

単一ファイルのアドオン: Tampermonkey ユーザースクリプトと外部スタイルシート。**ビルドなし、依存なし、バックエンドなし** — ファイルを1つ入れるだけで動きます。PR でバンドラー、npm 依存、コンパイル手順を持ち込まないでください。

### ディレクトリ構成

| パス | 内容 |
|---|---|
| `scripts/bluray/legacy/` | bluray パネルのリリース版、1バージョンにつき1ファイル |
| `scripts/bluray/docs/` | クイックスタート、ガイド、アーキテクチャ、開発メモ |
| `scripts/PTScripts/` | トラッカー向け小物ツール集。上流 `DaMauu/Scripts` に追随 |
| `styles/r/` | トラッカー向けテーマスタイル |
| `pta/` | ローカルのトラッカー構成をまとめたページ |

### バージョン規則

- **bluray**: ファイル名 `pt-bluray-assistant-v0.0.0.N.user.js`、4つのセグメントを増加。**旧版は絶対に上書きも削除もしない** — 変更したら新しいファイルを追加する。`@version` ヘッダー、パネルタイトル、注入ログの行の3か所を揃えること。
- **styles**: 1スタイルにつき1ファイル。変更時にバージョンを上げて tag を打つ。古い tag は永久に残すので、ユーザーはロールバックできる。
- **PTScripts**: このリポジトリはファイルが残っていることだけを保証する。上流 `DaMauu/Scripts` が正であり、変更はまず上流に出してから同期する。

### 提出前の確認

1. スクリプトが Tampermonkey に入り、対象サイトで実際に動くこと。「理論上動く」ではだめ。
2. どのトラッカータイプで検証したか（NexusPHP / UNIT3D / Gazelle / f3nix）を書く。サイト名があると助かる。
3. デバッグ用の `console.log`、ローカルパス、テストアカウントを消す。
4. ローカルの実データをコミットしない: `data/site-defs/` と `pta/data/site-arch.local.csv` は gitignore 済み。`git add -f` で強制追加しない。
5. **絶対にコミットしない**: Cookie、passkey、Tracker キー、API キー、個人情報を含むスクリーンショット。

### コミットメッセージ

何を変え、どのモジュールに触れたかを短く書く。例えば:

```
bluray: 修复 UNIT3D 站点填单时海报字段丢失
styles/r: 调深列表分隔线
```

中国語でも英語でも構いません。

### Pull Request

- 1つの PR では1つのことだけ。無関係な整形を混ぜない。
- 説明に書く: 動機、影響するモジュール、検証方法と結果、旧版ファイルに触れるかどうか。
- パネルやスタイルの変更ではスクリーンショットを添える。ただしアカウントとキーは隠す。

### Issue

バグや要望はテンプレートで Issue を立てる。セキュリティの問題は公開 Issue にせず、[SECURITY.md](../../SECURITY.md) を参照する。
